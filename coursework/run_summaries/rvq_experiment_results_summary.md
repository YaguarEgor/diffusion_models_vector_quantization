## full-XTX post-RVQ recoding

`full-XTX recode` был включен всегда, если XTX доступен. Это не finetuning в стиле VQDM: codebooks фиксируются, затем улучшаются discrete codes через coordinate descent / beam-like update под полный XTX.

Статистика по 150 завершенным recode-вызовам:

| Metric | Value |
|---|---:|
| count | 150 |
| relative objective improvement mean | 47.53% |
| relative objective improvement median | 50.26% |
| relative objective improvement min | 21.87% |
| relative objective improvement max | 58.48% |
| updates mean | 214026.7 |
| updates median | 119746.5 |

Вывод: recoding явно полезен для full-XTX objective и его стоит оставлять включенным всегда. Это дешевая стадия относительно обучения кодбуков и не является обновлением весов модели или codebooks.

## Что можно безопасно написать в курсовой

1. RVQ позволяет перебирать больше архитектурных вариантов, чем AVQ/VQDM, потому что не требует дорогого beam search при обучении всех кодбуков.
2. В этом раннем sweep увеличение `d` с 8 до 16 не улучшает качество и почти удваивает время обучения кодбуков.
3. На завершенной точке `4.15 bpp` ортогональное Hadamard-преобразование улучшает качество относительно noH для `d=8`.
4. На низких bpp пока нельзя честно утверждать, что Hadamard улучшает noH, потому что noH на `3.15` и `2.15` не успел завершиться.
5. full-XTX recoding после RVQ дает большой выигрыш по activation-aware objective без finetuning весов модели.

## Что не успело посчитаться

- `noH` для `3.15 bpp` и `2.15 bpp`;
- K-ablation (`K=128`, `K=512`);
- Conv2d stage;
- all-linear / broader layer stage;
- HPSv2;
- финальный `rvq_funnel_results.json`;
- `FINAL RVQ FUNNEL SUMMARY`.

## Рекомендации для следующего запуска

Приоритеты:

1. Убрать `d=16` из основного sweep, оставить только как уже зафиксированную отрицательную абляцию.
2. Добить `d=8` на низких bpp: `2.15` и `3.15` важнее всего.
3. Обязательно считать `H` и `noH` отдельно, чтобы можно было честно писать про вклад ортогонального преобразования.
4. После этого запускать K-ablation для `d=8`: `K=128`, `K=256`, `K=512`.
5. full-XTX recoding оставить включенным всегда.

Практический вывод по текущему запуску: для основной линии исследования сейчас наиболее перспективны `d=8`, `K=256`, Hadamard `H8/H16`, особенно низкие bpp.
